# Спецификация формата `.poler` / `.pqw` — v1

**Статус:** реализовано в крейте `pqw` v0.1.0 (POLER-Quantum-RS).
**Контракт:** формат стабилен с этой версии, версионируется полем
`format_version`; любой узел POLER Mesh может исполнить состояние без
переквантования.

## 1. Назначение

`.poler` / `.pqw` (POLER Quantum Weights) — контейнер фазовых весов POLER[Ψ]:
разреженное состояние `p ∈ [−1, 1]^d` в квантованном фазовом представлении.
Оба расширения обозначают один и тот же контейнер v1:

- `.poler` — полное состояние экосистемы POLER;
- `.pqw` — квантовые веса (подмножество того же контейнера).

Цели формата: zero-copy mmap-загрузка без распаковки, сжатие по ε-значимости
(sparse LENS), готовность к multiplier-less исполнению (триты + кривизна),
встроенная проверка целостности и McWeeny-инвариант `P² = P`.

## 2. Терминология

| Термин | Значение |
|---|---|
| **Дуга** | ненулевой компонент состояния: пара (индекс, фаза) |
| **Трит** | грубая фаза дуги ∈ {−1, 0, +1}; предельная точка McWeeny-потока |
| **Кривизна σ** | 6-битная локальная деформация на дуге, σ ∈ [0, 63] |
| **LENS** | механизм ε-значимости: дуги с \|p\| < ε не хранятся вовсе |
| **nnz** | число хранимых дуг (после LENS) |
| **d_pol** | размерность состояния |

## 3. Байтовая карта

Все числа — **little-endian**. Файл = фиксированный заголовок 128 байт +
переменный payload (топология, затем фазовые блоки). Лишних байтов после
конца payload быть не должно.

| Смещение | Размер | Поле | Тип |
|---|---|---|---|
| `0x00` | 8 | magic `POLER_QW` | байты `50 4F 4C 45 52 5F 51 57` |
| `0x08` | 4 | `format_version` | u32, = 1 |
| `0x0C` | 4 | `d_pol` | u32, ≥ 1 |
| `0x10` | 4 | `eta` | f32 |
| `0x14` | 4 | `gamma` | f32 |
| `0x18` | 4 | `rho` | f32 |
| `0x1C` | 4 | `epsilon_threshold` | f32 |
| `0x20` | 8 | `mcweeny_residual` | f64 |
| `0x28` | 24 | `payload_digest` | SHA-256 → первые 24 байта |
| `0x40` | 8 | `topology_offset` | u64, = 0x80 |
| `0x48` | 8 | `topology_len` | u64 |
| `0x50` | 8 | `phase_offset` | u64 |
| `0x58` | 8 | `phase_len` | u64 |
| `0x70` | 8 | `reserved` | u64, = 0 |
| `0x60` | 8 | `nnz` | u64 |
| `0x68` | 8 | `flags` | u64 |
| `0x78` | 8 | `header_checksum` | u64, FNV-1a64 по `0x00..0x78` |
| `0x80` | `topology_len` | индексы дуг | nnz × u16 или nnz × u32 LE |
| `0x80 + topology_len` | `phase_len` | фазовые блоки | nnz × 1 байт |

Инварианты связей:

```text
topology_offset == 0x80
topology_len    == nnz × index_width        (2 или 4 — по флагу INDEX16)
phase_offset    == 0x80 + topology_len
phase_len       == nnz
file_len        == phase_offset + phase_len
nnz             ≤ d_pol
```

## 4. Фазовые блоки

Один байт на дугу:

```text
бит 0..1 — трит: 0b00 = −1, 0b01 = 0, 0b10 = +1, 0b11 — зарезервировано
бит 2..7 — кривизна σ ∈ [0, 63]
```

Декодирование:

```text
p̂  = trit · (σ / 63)              — значение трека
θ̂  = arccos(p̂)                    — фазовый угол для Ry(arccos p)
```

Квантование (запись): ближайший узел сетки `trit · k/63`; `σ = round(|p|·63)`;
`σ = 0` → явный нуль (трит `0b01`). Граница ошибки: `|p̂ − p| ≤ 1/126`.

Три уровня представления нуля:

1. **LENS-фон**: `|p| < epsilon_threshold` → дуга не хранится (нет индекса);
2. **Явный нуль**: дуга хранится с тритом 0 (экспертный контроль топологии);
3. **Чистые фазы** ±1: трит ±1 с σ = 63 — предельные точки McWeeny-потока.

Multiplier-less исполнение: умножение на трит — это знак (negate/pass), а
`σ/63 = Σ битов σ · 2^(−k)` — сумма степеней двойки, т.е. сдвиги и сложения.

## 5. Sparse LENS-топология

Индексы хранимых дуг, **строго возрастающие**, каждый `< d_pol`:

- флаг `INDEX16` (u16-индексы): допустим при `d_pol ≤ 65536`, экономит 2
  байта на дугу; writer выбирает автоматически, `force_index32()` запрещает;
- иначе u32-индексы.

Сортированность + уникальность дают O(nnz) валидацию и бинарный поиск по
топологии без дополнительного индекса.

## 6. McWeeny-подпись (`0x20..0x40`)

Формат фиксирует отклонение от идемпотентности на момент записи:

```text
mcweeny_residual = max по хранимым дугам |λ² − λ|,  λ = (1 + p̂)/2
```

- `0` — все дуги суть чистые фазы ±1 или файл пуст: `P² = P` точно;
- `0.25` — максимум (явный нуль: λ = 1/2, максимально смешанное состояние).

Один шаг очистки `λ' = 3λ² − 2λ³` (эквивалентно `P_new = 3P² − 2P³` на
диагональном представлении) стягивает `|p| > 0.9` к чистой фазе за 2 такта
(0.9 → 0.9868 → 0.9997). API: `reader.purified()` / `purify_steps(n)` /
`mcweeny::purify_state`.

`payload_digest` — первые 24 байта `SHA-256(байты файла с 0x80 до EOF)`
(топология + фазовые блоки, они континуальны).

## 7. Контроль целостности

| Механизм | Покрытие | Когда проверяется |
|---|---|---|
| `header_checksum` (FNV-1a64) | `0x00..0x78` | всегда, при разборе |
| `payload_digest` (SHA-256 → 24 б) | весь payload | **лениво**: `verify_payload()` |

Ленивость digest — осознанное решение: «instant cold start» не должен
упираться в хеширование гигабайтного фазового графа при открытии. Структурная
валидация (смещения, длины, сортированность, триты) выполняется всегда.

## 8. Флаги

| Бит | Имя | Значение |
|---|---|---|
| 0 | `INDEX16` | топология в u16-индексах |
| 1 | `CURVATURE` | фазовые блоки содержат кривизну; v1: **обязателен** |
| 2..63 | — | зарезервированы, обязаны быть 0 |

Зарезервированное слово `0x70` и все биты ≥ 2 обязаны быть нулями — читатель
v1 отвергает файлы с ненулевыми значениями (строгая прямая совместимость:
v2-файлы не будут молча интерпретированы неправильно).

## 9. Порядок валидации читателя

1. `len ≥ 0x80` → иначе `Truncated`;
2. magic → `BadMagic`;
3. `format_version == 1` → иначе `UnsupportedVersion`;
4. `header_checksum` → `CorruptHeader`;
5. `flags` / `reserved` → `ReservedBits` / `UnsupportedFlags`;
6. `d_pol ≥ 1`, связи смещений и длин → `Layout` / `InconsistentTopology`;
7. `file_len` точно → `Truncated` / `Layout`;
8. семантика payload: сортированность/границы индексов, отсутствие трита
   `0b11` → `BadIndex` / `UnsortedTopology` / `ReservedTrit`;
9. (опционально) `verify_payload()` → `CorruptPayload`.

## 10. Ин-мемори сборка и стриминг (v0.1.2)

`PqwWriter::write_to_vec(&mut Vec<u8>)` дописывает контейнер в чужой
буфер без промежуточного файла: zero-storage стриминг для графового
поиска (`poler-engine`), где чанки не должны касаться диска. Ранее
записанное содержимое буфера сохраняется — один буфер переиспользуется
между чанками. `to_bytes()` делегирует `write_to_vec`.

`pqw::stream::TextPhaseEncoder` — эталонный кодировщик чанков:
Unicode-токены → FNV-1a64 (младшие биты — координата `h mod d_pol`,
старший бит — полярность) → накопление знаков → L∞-нормализация →
ε-плотность LENS через `add_state`. Детерминизм: одинаковый чанк даёт
идентичные байты контейнера.

## 11. Детерминизм и совместимость

- Writer детерминирован: одинаковый набор дуг и гиперпараметров даёт
  побайтово идентичный файл (BTreeMap-упорядочение);
- Записываются бит-точные f32/f64 — никаких текстовых округлений;
- `format_version = 2` (план): режим без кривизны (4 дуги/байт), блочный RLE
  топологии, веса `J = A − Aᵀ` верхним треугольником, счётчик такта `t` в
  зарезервированном слове.
